How it works

The rules it plays by

i.

One document, always current.

There's one page and it's always the latest version. Each instruction you give ("draft", "tighten", "add an example here") is applied to that page. Select some text first if you want to aim at a particular passage.

ii.

Edits arrive as suggestions.

Additions in green, deletions struck through, grouped under the instruction that caused them. Accept one, everything from an instruction, a handful you pick, or the lot. J, K, A and R work from the keyboard.

iii.

Nothing changes until you say so.

The agent's edits wait for you. The one exception is the first draft of an empty page, since there's nothing there yet to protect.

iv.

You can still just type.

Fix a typo yourself. Tell one change to be shorter and leave the rest alone. Highlight a paragraph and press ⌘J to ask about it in a thread off to the side.

v.

Every version has a label.

"add summary at top", "accepted 3 changes", "edited §Approach". History records who made each change and why, and you can preview or restore any of them.

vi.

Bring your own AI.

Margins runs the official Copilot, Codex and Claude command-line tools on the plan you already pay for. Your documents are ordinary files in ~/Documents: a .margins file and a plain .md copy.

Under the hood

There's a proper agent behind the page.

It can search the web, fetch pages, read files and, if you allow it, run commands. You watch it work on the instruction card instead of in a transcript. Point a document at a project folder and say "implement this", and it will edit the code too. Whatever it ends up doing, the changes to your document still arrive as suggestions.
