Document-first agent UI

You give instructions in plain language, and the agent's answer is a change to the document instead of a chat reply. All three mockups use the same example design doc. Responses are scripted, so any input you type steps through a fixed set of demo edits.

A · Tracked changes

Your instructions stay in a list on the left. Each one changes the document as a suggested edit you can accept or reject, and every instruction saves a new version you can go back to.

 B · Margin directives

The document fills the screen. Click a block to aim an instruction at it. Your requests, the agent's notes and its questions appear in the margin next to the text. Start an instruction with “always” or “never” to save it as a rule for the whole document.

 C · Brief → Document

Your input is condensed into an editable brief, and the document is rebuilt from that brief. Each section shows which brief items it came from. Turn items on or off to see how the document changes, and use the history bar at the bottom to view past versions.

 Later · Outline / TOC

Three ways to show a map of the headings: a rail beside the page, minimap ticks on the edge, or a tab in the sidebar. The app ships the rail, which turns into ticks when the window is narrow.
