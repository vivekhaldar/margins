Rate Limiting for the Public API

Design doc · Draft · Platform team

Summary

A few heavy API callers degrade latency for everyone and page on-call. We propose per-key token-bucket limits at the edge gateway, rolled out behind a shadow mode.

Goals

Keep p99 latency under 300 ms during spikes up to 10× baseline. No single API key consumes more than 5% of gateway capacity. Fewer than 0.1% of currently well-behaved requests receive a 429.

Proposal

Use a token bucket per API key, enforced at the edge gateway. Limits are configured per plan tier and stored in the config service.

Agent · question
Should internal service-to-service traffic be subject to these limits?

Requests over the limit receive HTTP 429 with a Retry-After header. Responses always include X-RateLimit-Remaining so clients can self-throttle.

Rollout

Ship in shadow mode (log only) for two weeks, then enable for the free tier, then all tiers.
