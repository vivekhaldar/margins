Rate Limiting for the Public API

Design doc · Draft · Platform team

Summary

We want to add rate limiting to the public API because some customers send too many requests, which sometimes causes problems for other customers and also pages our on-call engineers. This document proposes an approach for doing that.

Goals

  • Protect the API from abusive traffic
  • Be fair to customers
  • Don't break existing integrations

Proposal

Use a token bucket per API key, enforced at the edge gateway. Limits are configured per plan tier and stored in the config service.

Requests over the limit receive HTTP 429 with a Retry-After header.

Rollout

  1. Ship in shadow mode (log only) for two weeks
  2. Enable for free tier
  3. Enable for all tiers
